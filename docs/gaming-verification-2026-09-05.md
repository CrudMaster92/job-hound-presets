## Patterns for scaling

- **Detect the ATS before writing selectors.** Public Greenhouse, Lever, Ashby, SmartRecruiters, Workable, Recruitee, BambooHR, Teamtailor JSON Feed, Breezy, and Pinpoint endpoints cover most companies with compact reusable mappings.
- **Treat a 200 response as discovery evidence, not validation.** Old boards often return an empty feed, a general-application form, or redirect every job to a careers landing page. A live runtime run plus representative source-link checks catches these cases.
- **Prefer stable IDs and direct source URLs.** Avoid session IDs in links and URL hashes derived from mutable text. When an official page wraps an ATS, use the public ATS ID and human-facing detail URL.
- **Mark bounded feeds as partial.** Keyword searches, fixed-size feeds, regional boards, and unsupported path pagination must not close unseen jobs. The collection records those limits per monitor.
- **Use one company identity with scoped monitors.** Amazon Games and Microsoft Gaming reuse existing Amazon and Microsoft identities, while the Gaming and Fortune collections select the appropriate monitor IDs.
- **Validate logos as images in a browser.** HTTP status checks miss HTML error pages, tiny social icons, transparent marks, and logos that vanish on dark backgrounds. Decode checks plus a light/dark contact sheet scale well.
- **Run candidates concurrently, promote only matched evidence.** Hash each normalized recipe with its run evidence so a regenerated or edited candidate cannot be promoted on stale results.
